# Engine improvement progress — 17 September 2026

## 2026-10-01: separately selected pthread artifact for Box3D (roadmap item 21)

[Threaded engine](THREADED_ENGINE.md) adds `public/box3d/box3d-mt.{js,wasm}`, which solves one world on up to 32 threads (the calling thread included) through Box3D's own task-callback scheduler. The shipped single-threaded artifact and the qualified bridge `wasm/box3d_web.c` are unchanged, and the single-threaded artifact remains the fallback. With it as the oracle, simulation state is bit-identical over the 800-scene catalog at 1, 2, 4 and 8 workers (3,322 exact comparisons, 0 mismatches), across mid-run worker changes, awake-body threshold crossings and four interleaved native worlds. That was run in Node v26.0.0 only.

Every timing is load-contaminated: load average 39–121 on 32 CPUs, and no window met the benchmark's load ≤ 16 rule. Under that load 4–8 workers gained about 1.4–2.8× at 4,096–16,384 awake bodies, were no faster at 1,024 (0.68–0.98× in the final matrix), and per-run spread inside one configuration was 1.2–3.6× (median 1.6×). The quiet-machine speedup of the shipped artifact is UNKNOWN. This is not a 100× result on any scorecard; rendering, interactive capacity and engineering capability are unchanged. The only route identified toward 100× rigid-body capacity is a separate GPU-resident solver on a restricted shape set, which is reasoned, unmeasured and not started.

Open: two unexplained Node 26.0.0 events (one SIGILL and one exit hang after a printed result, in 116 threaded runs; none in 109 single-threaded runs), not attributed to or cleared for the artifact; and no deployed host sends COOP/COEP, so threads are live only under Vite dev/preview and `?threads=off` keeps any page single-threaded. Roadmap item 21 is recorded `implemented`, not `verified`. Evidence: [run folder](../benchmarks/results/engine-100x/runs/threaded-engine-20261001-01/README.md).

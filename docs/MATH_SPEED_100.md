# 100 ways to improve the math and speed of Metal press

Audited 11 September 2026. This is a focused addition to the [original engine roadmap](/Users/commander/box3d-WEBGPU/docs/ENGINE_100X_ROADMAP.md), whose 100 items and status remain intact. The scope follows the currently open Metal press study and the runtime it shares with canopy and bridge.

M009 is implemented and enabled for fresh Studio UI runs. Its compensated three-component norm preserves 1,884 sampled physical checkpoints across 38 Node scenarios plus mass/load edits, and 240 browser checkpoint samples. Controlled CPU throughput is 1.387× for the default press, 1.397× for the aluminum-draw preset, 1.469× for canopy and 1.359× for bridge; all controls and legacy performance gates pass. These are physics-step measurements, not browser FPS. Forty-two production tests, TypeScript and native WebGPU run/replay/pause/reset checks pass. M001 and the combined M003/M004/M020 trial were rejected and retained; M018, M064 and M097 now have a qualified analytical working-tool query and normal-response foundation: 4,800 mesh distance samples and 3,680 complete sweeps pass, with full Studio integration still open. Controlled query throughput is 1.363 times the preceding analytical candidate across 2,395 common-resolved oblique cases, with all tool, unchanged-control and p95 gates passing; this is a standalone query measurement. The other 92 entries remain proposals. The original engine roadmap status is unchanged. See the [norm experiment report](/Users/commander/box3d-WEBGPU/docs/STUDIO_NORM3.md) and [press contact qualification](/Users/commander/box3d-WEBGPU/docs/PRESS_CONTACT.md). The [first trial comparison](/Users/commander/box3d-WEBGPU/benchmarks/experiments/math-speed-audit-20260911/strain-comparison.json), [timing](/Users/commander/box3d-WEBGPU/benchmarks/experiments/math-speed-audit-20260911/strain-timing/result.json) and [restoration](/Users/commander/box3d-WEBGPU/benchmarks/experiments/math-speed-audit-20260911/restoration.json) remain historical evidence.

The audit Node profile used the baseline 2 mm mild-steel, flat-punch setup: **957 nodes, 5,434 links, 12 constraint passes and 13 contact passes per tick**. After a separate 240-tick warm-up, 1,200 profiled ticks took **3195.9 ms**. About **82.5%** of sampled time was in the constraint step and **11.8%** in contact/tool evaluation. This diagnostic includes profiler and checkpoint-sampling overhead; it is one run, and does not measure browser FPS or establish a speedup. [Frozen profile and source identity](/Users/commander/box3d-WEBGPU/benchmarks/experiments/math-speed-audit-20260911/profile-summary.json).

The current code already has worker execution, backpressure, reusable snapshots, interpolation, topology caching and active-constraint compaction. The earlier packed solver failed its CPU gate and remains experimental. These entries extend those foundations rather than count them again as new wins.

**Priority:** P0 removes an observed cost or establishes essential correctness; P1 is the next substantial wave; P2 is conditional research or a workload-dependent optimization. **Kind:** exact = preserve physical arithmetic and outputs; numerical = qualify a changed solver or physical model; presentation = preserve a declared visual error bound; qualification = establish a measurement or acceptance gate. New physics may cost more CPU. Solver alternatives require comparison. The ratios from separate optimizations must not be multiplied into an engine-wide claim.

Start with **M009, M003, M011, M087, M008, M021, M022, M031, M064, M093**. The recorded priority order begins with the dominant norm calculation, repeated contact work and redundant geometry updates; consult each item's current status before starting a trial. Physical units/masses, compliant constraints and correct tool normals form the main mathematical upgrade.
